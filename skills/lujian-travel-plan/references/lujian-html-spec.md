# 旅笺增强 HTML 产物规范

生成一个可直接导入“旅笺”Android App、浏览器直接打开且可部署到 GitHub Pages 的 UTF-8 无 BOM 单文件 HTML。检索、证据、行程 JSON 与地图链接规则继续使用本技能原有契约，本规范只约束最终产物。

## 强制元数据

HTML 中必须且只能出现一个结构化数据块：

```html
<script id="lujian-plan" type="application/json">
{"schemaVersion":1,"title":"……","destinations":[],"days":[]}
</script>
```

顶层字段：

- `schemaVersion`：固定为数字 `1`。
- `title`：计划名称。
- `headline`：手机与电脑共用的大字号主标题；优先取 `trip.headline`，未提供时按天数、目的地和风格生成，例如“**五天说走就走，把大连吃个痛快。**”。
- `destination`、`dateRange`、`travelers`、`style`、`baseArea`：来自 `trip`，未知时留空，不猜测。
- `budget`：总预算显示值。
- `destinations[]`：至少保留目的地名称；只在输入有真实坐标时写 `latitude`、`longitude`。
- `days[]`：`id`、`label`、`title`、`summary`、`budget`、`items[]`。
- `places[]`、`warnings[]`、`sources[]`、`assumptions[]`：完整保留原行程证据链。

每个 `days[].items[]` 至少写入：

- `id`、`time`、`title`、`category`、`cost`、`notes`。
- 可用时写入 `placeId`、`transport`、`mapLinks`、`sourceIds`、`warningIds`。
- `notes` 输出为字符串，原输入为数组时用换行连接，适配旅笺 `schemaVersion=1` 解析器。

禁止把 JSON 写进 JavaScript 变量代替该数据块；禁止遗漏 `type="application/json"`。

## 页面模板

- 除固定版本 MapLibre CSS/JS 外，全部样式与交互必须内联；不得依赖 Tailwind、Bootstrap 或其他外部脚本/样式表。
- 使用纸张底色 `#FAF6EF`、墨色 `#2A2520`、珊瑚橙 `#FF6B4A`、金色 `#F2B43A`。
- 标题使用系统可用中文衬线字体，数字与元数据使用无衬线字体；字体不可用时自然降级。
- 手机与电脑的大字号主标题必须逐字一致；顶部品牌区继续显示计划名或“旅笺”，左侧图标统一使用显式 `font-weight: 900` 的“笺”字，不得依赖父元素继承。
- 卡片使用粗描边、圆角和克制的偏移阴影，保持“印刷旅行手账”而非通用蓝色 H5 风格。
- 同一个 HTML 必须同时包含手机与电脑两套响应式展示，二者读取同一个 `script#lujian-plan`；不得拆成两份文件或复制两份结构化数据。
- 手机与电脑都保留旧版“行程 / 地图”两个 Tab；两个入口共享同一个视图状态和地图实例，切回行程时不得重置已选日期；地图页共用一份行程与点位数据，不能另写一套路线。
- live 地图与文件内静态兜底统一使用旧版插针：带序号的 `pin-dot`、短引线 `pin-line`、地点名称与时间组成的 `pin-card`；禁止退化为单独的水滴圆点。窄屏可隐藏引线和地点卡片，但插针序号必须保留。
- 地图上方恢复旧版 `地点 / 预计里程 / 移动时间` 三项统计；优先显示经过核对的 `days[].distanceEstimate` 与 `days[].durationEstimate`，缺失时才根据有效坐标和交通方式给出带“约”的估算，无足够坐标时显示“待补”。不得把“有效坐标 / 路线段”等实现计数当作面向用户的行程预估。
- 允许且只允许固定版本 MapLibre 的 CSS/JS 外部依赖；有地点坐标时加载当天路线，有目的地坐标但无地点坐标时至少加载目的地底图；底图、库或全部坐标不可用时必须展示文件内静态点位/连线或文字路线，不得白屏。
- 切换到无坐标日期时必须清空上一天的 live marker 与路线，不能残留旧点位；单个瓦片错误不得把已经加载成功的地图强制切回空白。
- 远程封面图只能作为可选增强；断网或无图片时必须保留纸张纹理与可读标题。
- 生成器的纸张色、墨色、珊瑚橙、金色、字号层级、卡片圆角和预算栏构图属于稳定视觉合同；除非用户明确要求改版，不得在普通内容更新中大幅改变。

## 手机视图（小于 `960px`）

- 顶部提供吸附的横向日期轴，每天一个按钮。
- 主视觉显示与电脑端完全相同的 `headline`，允许按中文逗号换成两行，但文本不得改变。
- 主标题末句下方使用旧版连续金色波浪线；波浪线必须是 CSS/SVG 图形，不得出现字符状乱码或点状渐变。
- 页面任一时刻只渲染一个 `.day-panel`。
- 点击日期和左右滑动当天内容都能切换；当前日期按钮自动滚动到可视区域中央。
- 切换使用短距离滑动加淡入，遵守 `prefers-reduced-motion`。
- 日期超过屏宽时只允许日期轴横向滚动，不得让正文横向溢出。
- 点击“地图”后隐藏手机单日正文与固定预算条，显示当天路线地图、日期切换和有序路段列表；切回“行程”恢复原选中日期。

## 电脑视图（大于等于 `960px`）

- 按桌面版“大连旅行计划”的构图显示：顶部粘性品牌栏、宽幅标题区、类型筛选、左侧纸张行程板、右侧深墨色粘性预算栏。
- 行程板一次展示全部天数，每天一列；**1–5 天必须完整铺满且不出现横向滚动条，只有大于 5 天时才允许行程板内部横向滚动**，不得把手机单日页放大居中代替。
- 每列显示 `Day N`、日期、行程数量、当天摘要和当天全部卡片；不同列高度相互独立。
- 卡片使用分类色块、图标、时间、标题、费用、分类标签和独立展开详情；展开不得联动其他卡片。桌面展开内容沿用旧版：11px 宋体/衬线说明文字、浅色下一程条、同为 11px 的单一紧凑地图按钮（高德优先，缺失时才回退百度），不在展开框内塞来源卡或并列的第二个地图按钮，也不得继承卡片标题的大字号。
- 提供“全部 / 美食 / 景点 / 住宿 / 其他”筛选，筛选只影响桌面卡片，不改变天数或手机端状态。
- 右侧预算栏显示天数、日期/人数/住宿信息、每日预算、总预算、假设说明和保存按钮。
- 行程板下方的“往返交通方案 / 住宿方案”使用两条紧凑折叠栏，默认收起；不得替换为抢占大面积页面的说明卡片。两栏按内容独立增高，打开一栏不得把另一栏的关闭状态拉成同高空框；有结构化交通班次、票价提醒和酒店备选时必须完整呈现。
- 电脑视图隐藏手机日期轴、手机固定预算条与底部预算弹层；手机视图隐藏全部桌面布局。
- 桌面“地图”Tab 复用同一个地图容器与路线状态；切换视口不得复制 MapLibre 实例或丢失当天路线。

## 内容完整性

- 当天行程按顺序展示时间、名称、类别、费用、说明和下一程交通。
- 每张地点卡独立展开/收起，不联动其他卡片。
- 手机详情保留相关高德/百度链接、避坑和小红书来源；优先 `mobileShareUrl`，网页 URL 只作备用。桌面详情遵守上文旧版紧凑结构。
- 地图路线默认按当天行程顺序连接；当数据提供 `mapStops`/`mapLegs` 时以显式路段为准。返酒店等闭环必须保留最后一段路线与路线列表项，但酒店只计作一个地点；数据未声明时不得擅自补闭环。
- 右侧每条路线左边保留旧版 22px 橙色编号大头针；地图右上角保留 `+ / − / DRAG` 控件。拖拽默认锁定，只有按钮显示 `DRAG ON` 时才允许拖动，缩放按钮始终操作当前在线地图。
- 只在相关卡片或提醒旁标注候选、地址缺失、营业时间未核实等不确定性，不单列“数据边界”。
- 显示当天预算、备选方案、当天提醒，并提供总预算明细。
- 无地址、坐标、提醒、图片或来源 URL 时显示简短空态，不输出失效按钮。
- `保存页面` 必须实际下载当前完整 HTML，文件名为 `lujian-travel-plan.html`。

## 验收

依次运行：

```bash
python scripts/generate_map_links.py itinerary.json --write
python scripts/validate_itinerary.py itinerary.json
python scripts/create_static_html.py itinerary.json lujian-travel-plan.html
python scripts/validate_lujian_html.py lujian-travel-plan.html --itinerary itinerary.json
```

最终确认：无 UTF-8 BOM、除固定版本 MapLibre 外无其他外部 CSS/JS、元数据可解析、天数与来源未丢失；`390px` 默认只显示第一天且点击/滑动可切换，旧版“行程 / 地图”切换双向可用并保留已选日期，手机与桌面共用同一大字号主标题和加粗“笺”字；`1440px` 的 5 天夹具必须完整显示 Day 1–5 且 `scrollWidth == clientWidth`，6 天夹具必须只在行程板内部横向滚动；桌面卡片展开为旧版紧凑结构；住宿交通为默认收起且高度互不牵连的两条富内容折叠栏；地图统计必须为 `地点 / 预计里程 / 移动时间`；带有效坐标的在线夹具必须进入 `.map-live`，live 与静态地图均须保留 `pin-dot + pin-line + pin-card` 旧版插针结构，路线列表逐条保留 22px 编号大头针，`+ / − / DRAG` 可用且拖拽默认锁定；显式返酒店路段必须同时出现在路线列表与地图线路中，无网或无坐标夹具必须保留静态/文字路线。

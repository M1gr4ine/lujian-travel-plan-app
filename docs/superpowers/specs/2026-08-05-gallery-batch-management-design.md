# 相册批量管理设计

## 目标

在计划内相册和底部全局相册增加统一的批量管理能力。用户可多选地点照片和自定义预览图，一次确认后删除应用私有副本；系统相册原图不受影响。

## 已确认范围

- 计划内相册与全局相册均提供“管理/完成”入口。
- 管理状态支持逐项选择、全选、取消全选和显示已选数量。
- 地点照片和自定义预览图均可选择。
- 删除自定义预览图后，计划恢复自动生成的默认预览图。
- 删除前统一二次确认，文案明确“仅删除旅笺私有副本”。
- 不新增回收站、撤销、跨设备同步或系统相册删除能力。

## 交互设计

### 通用管理状态

正常状态下，照片仍保持当前行为：计划内可查看大图或单张移除，全局相册可进入对应计划。点击“管理”后：

1. 图片右上角显示选择标记，点击图片只切换选中状态，不再打开详情或跳转。
2. 顶部出现“全选 / 已选 N 项 / 删除”操作条；再次点击入口显示“完成”并退出管理。
3. 在“按加入时间 / 按大头针”或“按加入时间 / 按计划”之间切换时，选择状态按稳定资源标识保留。
4. 全选覆盖当前相册中的全部可删除项目，不局限于当前分组或屏幕内可见项目。
5. 数据刷新后，已不存在的项目自动从选择集合移除；相册清空时自动退出管理。

### 自定义预览图

自定义预览图作为可删除项目参与选择，标签仍显示“封面”。确认删除后清空计划的自定义预览图字段、删除对应私有文件，并重新生成计划缩略图。自动生成的默认缩略图不作为相册项目，也不可选择删除。

### 删除确认

确认框按实际选择显示数量，例如“删除 4 张照片和 1 张自定义预览图？”。确认按钮使用危险色；取消后保留管理状态和当前选择。删除执行后清空已处理选择，失败信息沿用页面现有错误提示通道。

## 代码结构

### 选择模型与策略

新增独立的相册选择标识模型，区分地点照片和计划封面：

- 地点照片使用照片数据库主键作为稳定标识。
- 自定义预览图使用计划主键作为稳定标识。
- 选择策略负责全选集合、失效项收敛、删除数量摘要，不依赖 Compose 状态。

计划内相册与全局相册复用同一选择模型和管理操作条，两个页面只负责将现有展示项目映射为可选择项。

### 数据删除

`PlanRepository` 增加批量删除入口，一次接收照片 ID 集合与封面计划 ID 集合：

1. 在 Room 事务内校验并删除照片记录、清空自定义预览图字段，同时收集需要删除的私有路径。
2. 事务提交后在 IO 线程删除经过 `PlanMediaStore` 路径边界校验的文件。
3. 对移除封面的计划重新排队生成缩略图。
4. 文件已不存在视为幂等成功；数据库失败时不执行文件删除。

不修改数据库表结构，只扩展 DAO 批量查询、批量删除和批量清空字段的方法。

### 页面接线

- `PlanGalleryScreen` 接收批量删除回调，并保留现有单张删除能力。
- `GlobalGalleryScreen` 接收批量删除回调；正常状态下保持原有计划跳转。
- `LujianRoot` 和 `PlanDetailScreen` 将选择结果交给仓储层，并展示失败信息。

## 错误与边界

- 空选择时删除按钮禁用，不弹确认框。
- 只允许删除当前仓储中仍存在且与选择标识匹配的资源，避免过期界面误删。
- 同一照片在不同分组视图中仍对应同一个选择项，不能重复计数。
- 批量操作不会删除系统相册 URI 或外部文件。
- 私有文件删除失败不恢复已提交的数据库记录，但返回失败信息并保留安全的孤立文件；后续计划目录清理仍可回收。

## 验证方案

### 单元测试

- 选择标识在两种相册模式下保持稳定且去重。
- 全选、取消全选、数据刷新收敛和删除摘要正确。
- 同时选择照片与封面时生成正确批量请求。
- 私有路径校验继续阻止删除应用目录之外的文件。

### 仓储与数据库测试

- 批量删除照片记录并清理对应私有文件。
- 批量清空封面后恢复默认缩略图生成链路。
- 空集合幂等，过期选择不影响其他照片或计划。

### 虚拟机测试

- 计划内相册：进入管理、跨分类保留选择、全选、取消、确认批量删除。
- 全局相册：跨计划多选照片和封面，删除后两个相册同步刷新。
- 删除自定义预览图后，旅笺板恢复默认预览图。
- 删除后系统媒体库计数不变，重启应用后状态保持。
- 执行单元测试、Lint、Debug APK、AndroidTest APK 和 `connectedDebugAndroidTest`。

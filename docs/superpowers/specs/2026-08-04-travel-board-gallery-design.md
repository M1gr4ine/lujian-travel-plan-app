# 旅笺板、归档与计划相册设计

## 目标

在保留现有地图、计划详情和纸张便签视觉的前提下，完成三组能力：

1. 将“计划库”升级为可切换的“旅笺板”，区分“计划板”和“足迹板”，支持双向归档。
2. 在编辑页允许用户选择自定义预览图，并可更换或恢复自动封面。
3. 为行程活动卡片与地图大头针添加照片，并提供计划内相册与跨计划全局相册。

本功能从当前工作区的在制地图与详情改动继续开发；这些改动必须保留，不在设计提交中混入提交。

## 名称与信息架构

- 底部入口与页面总标题统一为“旅笺板”。
- 未归档计划所在视图称为“计划板”。
- 已归档计划所在视图称为“足迹板”。
- 点击左上角当前板标题即可在两个板之间切换。
- 归档只改变旅笺板分类。归档计划仍参与首页地图展示，也能打开、编辑、导出和删除。

## 旅笺板交互

两个板共用现有双列折角便签网格，但分别保留滚动位置和管理选择状态。

计划板管理栏提供“全选”“归档”“删除”；足迹板管理栏提供“全选”“移回计划板”“删除”。归档和移回支持批量操作，不弹破坏性确认框；删除继续保留确认框。

切换动画要求：

- 标题和副标题以短距离纵向滑动配合淡入淡出。
- 网格内容以约 280ms 的水平滑动配合淡入淡出，方向与板切换一致。
- 归档或移回时，卡片先缩小淡出，网格随后平滑补位。
- 系统启用“减少动态效果”时，退化为短淡入或直接更新。
- 切回某个板时恢复该板原滚动位置，不跳到顶部。

空状态分别使用“还没有待出发的计划”和“走过的旅程会收在这里”，计划板保留“添加计划”卡；足迹板不显示导入入口。

## 自定义预览图

编辑页在计划名称之前增加预览图卡片，提供“选择图片”“更换图片”和“恢复自动封面”。系统照片选择器支持选择单张图片，不申请宽泛存储权限。

选中后将图片复制到 App 私有目录，再基于该源图生成现有 640×640 卡片缩略图。系统相册中的原图保留，私有副本不写入 MediaStore，因此不会在系统相册出现第二张图片。

自定义预览图源文件同时作为计划内和全局相册中的“封面”项目展示。恢复自动封面时删除自定义源文件，重新执行现有 HTML 标题封面生成流程。

## 大头针照片与双层相册

行程页的每张活动卡片展开后提供“添加照片”和“查看照片”；地图页的每个地点卡片提供相同操作。行程卡片与地图地点通过现有 `itemId` 对齐，同一个地图大头针在两个页面使用同一照片分组。照片选择器支持一次选择多张图片。

图片按所属大头针复制到当前计划的 App 私有目录。计划详情的相册页签放在“行程 / 每日地图 / 预算”之后，只展示当前计划的照片与自定义预览图，并提供两种浏览模式：

- “按加入时间”：当前计划的所有地点照片与自定义预览图按加入时间倒序排列。
- “按大头针”：按地图大头针分组，组内按加入时间倒序排列；封面独立置于首组。

相册为空时显示添加引导。点击照片可查看大图，并可从大图页确认移除该私有副本；本期不包含编辑、滤镜、云同步和系统相册回写。

行程或地图中的“查看照片”切换到计划内相册并定位对应大头针分组；该大头针暂无照片时仍显示该分组的添加入口。

底部主导航在“首页 / 旅笺板 / 我”之外新增“相册”。该全局相册汇总所有计划的地点照片和自定义预览图，并提供两种浏览模式：

- “按加入时间”：跨计划按加入时间倒序展示，并标注所属计划与地点。
- “按计划”：先按计划分组，组内再按加入时间倒序展示。

全局相册只负责浏览、查看大图和跳回所属计划，不在计划之外创建无归属照片。

## 数据与文件设计

采用 Room 结构化记录配合 App 私有文件目录，不使用 JSON 塞入照片元数据，也不依赖运行时扫描目录恢复顺序。

`plans` 表新增：

- `archivedAt: Long?`：为空表示计划板，非空表示足迹板，并记录归档时间。
- `customCoverPath: String?`：相对于 `filesDir` 的自定义封面源文件路径。
- `customCoverAddedAt: Long?`：自定义封面的加入时间，用于相册时间排序。

新增 `plan_photos` 表：

- `id: Long`，自增主键。
- `planId: Long`，外键，删除计划时级联删除记录。
- `pinId: String`，对应行程卡片与地图大头针共享的 `itemId`。
- `pinTitle: String`，保存添加照片时的地点标题快照，原活动被编辑或删除后仍可识别照片归属。
- `relativePath: String`，相对于 `filesDir` 的私有文件路径。
- `addedAt: Long`，用于加入时间排序。
- `displayName: String?`，保留来源文件名用于无障碍描述。

数据库从 v1 升级到 v2，提供显式迁移：已有计划的三个新字段均为 `NULL`，照片表为空，不允许破坏性重建。

文件目录：

```text
plans/{planId}/cover/{uniqueName}.{ext}
plans/{planId}/photos/{pinKey}/{uniqueName}.{ext}
```

其中 `pinKey` 使用 `pinId` 的 SHA-256 前 24 位十六进制摘要，避免外部 HTML 中的大头针 ID 形成非法路径。文件名由应用生成，目录位于内部 `filesDir`，不会被系统媒体扫描。数据库只保存相对路径；所有读取需校验规范化路径仍位于 `filesDir` 内。

## 数据流与一致性

图片导入顺序固定为：校验 MIME 与可读流 → 复制到临时文件 → 原子改名到目标目录 → 写入数据库。任一步失败都删除临时或目标残留，不创建照片记录。

封面保存成功后再更新 `customCoverPath` 并触发缩略图生成；生成失败时保留原缩略图并提示用户重试。替换封面完成后清理旧自定义源文件。

删除单张照片先删除数据库记录，再清理文件；若文件删除失败，记录已经不可见，后续计划目录清理可再次回收。删除整个计划时沿用计划级目录递归清理，并依赖数据库外键级联移除照片记录。归档和移回只更新 `archivedAt`。

## 组件边界

- `PlanRepository`：归档、恢复、封面复制、照片复制、查询与清理的唯一业务入口。
- Room DAO：只负责计划状态与照片记录的事务操作。
- `PlanLibraryScreen`：板切换、管理选择和网格动画，不直接操作文件。
- `EditPlanScreen`：发起单图选择并展示封面状态。
- `NativePlanReader`：维护当前页签、日期和大头针相册定位请求。
- 计划内相册组件：渲染当前计划的时间流或大头针分组，并发起多图选择。
- 全局相册组件：聚合所有计划并按时间或计划分组，只发送“打开所属计划”的导航意图。
- 行程和地图卡片：发送“为此大头针加图”或“打开此大头针相册”的意图。

## 验收与测试

单元与仪器测试覆盖：

- v1 到 v2 数据库迁移保留原计划。
- 计划板和足迹板筛选、批量归档、批量移回与删除。
- 私有相对路径校验、复制失败回滚和计划删除清理。
- 自定义封面选择、更换、恢复自动封面。
- 单个大头针多图、跨大头针分组、按加入时间倒序。
- 行程与地图卡片共享同一大头针照片分组，并能跳转定位。
- 全局相册按加入时间和按计划分组。
- 板切换后各自滚动位置保持，减少动态效果策略生效。

虚拟机回归覆盖：安装升级包并保留已有计划；完成归档与恢复；选择、替换和恢复封面；从行程和地图分别为至少两个大头针添加多张图片；切换计划内两种相册浏览模式；从行程与地图卡片跳转对应分组；在全局相册切换按时间和按计划浏览；重启应用确认数据仍在；打开系统相册确认没有生成重复媒体项。

## 非目标

- 不删除或移动系统相册原图。
- 不把私有图片发布到 MediaStore。
- 不增加云端同步、相机拍摄、照片编辑、滤镜或跨计划照片共享。
- 不改变归档计划在首页地图上的可见性。
